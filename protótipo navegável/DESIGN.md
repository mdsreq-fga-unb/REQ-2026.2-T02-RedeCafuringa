## Authority

Este arquivo e `PROJECT_CONTEXT.md §8` são a autoridade humana para design. O registry `protótipo navegável/assets/design-tokens.json` e o CSS `protótipo navegável/assets/design-tokens.css` são derivados revisados. Propostas de `ui-ux-pro-max` não substituem estes valores.

## Direction

Interface acolhedora, territorial, editorial e acessível. A landing page prioriza missão, pessoas, comunidade e APA de Cafuringa antes das funcionalidades. A plataforma deve parecer uma ponte de confiança, não um marketplace agressivo.

## Approved foundations

- Display: `Lora`
- Body: `Atkinson Hyperlegible`
- Icons: Phosphor ou SVG acessível; nunca emoji estrutural
- Base unit: `4px`, com ritmo predominante de `8px`
- Breakpoints: `640px`, `768px`, `1024px`, `1280px`
- Minimum interactive target: `44×44px`
- Motion: `150–300ms`, com `prefers-reduced-motion`
- Token registry: `protótipo navegável/assets/design-tokens.json`
- Generated token CSS: `protótipo navegável/assets/design-tokens.css`

## Product visual rules

- Produtos, experiências, hospedagens e workshops devem ter tipos explícitos.
- Pré-reserva não é confirmação de reserva.
- Pix é simulado no protótipo e não representa cobrança real.
- Localização é aproximada por padrão.
- Certificação não pode ser inventada ou afirmada sem fonte validada.
- Feedback do visitante é privado.
- Experiências e hospedagens devem apresentar contexto, anfitrião, capacidade, duração, regras e o que está incluído.
