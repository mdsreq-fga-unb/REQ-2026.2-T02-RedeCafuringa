## Critérios de Aceitação (MVP)

A tabela a seguir apresenta os requisitos funcionais selecionados para compor o MVP (Produto Mínimo Viável) da Rede Cafuringa. Para cada requisito, é apresentada a História de Usuário (HU) correspondente, mantendo a relação de um para um entre requisito funcional e história de usuário. Também são definidos os Critérios de Aceitação (CA), que estabelecem as condições que devem ser atendidas para que a funcionalidade seja considerada implementada e validada. Dessa forma, os critérios permitem verificar objetivamente se cada requisito previsto para o MVP foi atendido pela solução.

| **RF** | **Requisito Funcional** | **HU relacionada** | **Critérios de Aceitação** |
| :----- | :---------------------- | :----------------- | :------------------------- |
| **RF01** | Cadastrar perfil de consumidor | **HU01** — Como consumidor ou visitante, quero cadastrar meu perfil na plataforma, para acessar funcionalidades e interagir com produtores e experiências. | **CA01:** O sistema deve permitir o preenchimento dos dados obrigatórios do consumidor.<br>**CA02:** O sistema deve validar os dados informados antes de concluir o cadastro.<br>**CA03:** Após o cadastro válido, o sistema deve criar o perfil e informar sua conclusão. |
| **RF02** | Cadastrar perfil de produtor | **HU02** — Como produtor ou responsável por uma iniciativa, quero cadastrar meu perfil de produtor, para divulgar produção, produtos e experiências. | **CA01:** O sistema deve permitir o preenchimento dos dados obrigatórios do produtor.<br>**CA02:** O sistema deve validar os dados informados antes de concluir o cadastro.<br>**CA03:** O perfil do produtor deve ficar disponível para utilização das funcionalidades destinadas a produtores. |
| **RF03** | Cadastrar usuário admin | **HU03** — Como responsável pela administração, quero cadastrar usuários administradores, para permitir apoio no gerenciamento da plataforma. | **CA01:** O sistema deve permitir que um administrador cadastre outro usuário com perfil administrativo.<br>**CA02:** O sistema deve exigir os dados obrigatórios para criação da conta.<br>**CA03:** O novo usuário deve receber as permissões correspondentes ao perfil administrativo. |
| **RF04** | Consultar usuários cadastrados | **HU04** — Como administrador, quero consultar os usuários cadastrados, para acompanhar e administrar os perfis existentes. | **CA01:** O sistema deve apresentar a relação de usuários cadastrados ao administrador.<br>**CA02:** A consulta deve apresentar informações suficientes para identificar cada usuário.<br>**CA03:** Usuários sem registros devem receber uma indicação de que não há resultados. |
| **RF09** | Autenticar usuário | **HU09** — Como produtor cadastrado, quero cadastrar meus produtos, para divulgar minha produção e permitir consulta dos consumidores. | **CA01:** O produtor autenticado deve conseguir iniciar o cadastro de um produto.<br>**CA02:** O sistema deve exigir os campos obrigatórios definidos para o produto.<br>**CA03:** Após o cadastro válido, o produto deve ser associado ao produtor responsável. |
| **RF10** | Recuperar acesso à conta | **HU10** — Como consumidor ou visitante, quero consultar o catálogo de produtos, para encontrar alimentos e outros produtos oferecidos. | **CA01:** O sistema deve apresentar os produtos disponíveis para consulta.<br>**CA02:** Cada produto deve apresentar informações suficientes para sua identificação.<br>**CA03:** O catálogo deve permitir ao usuário acessar os detalhes de um produto. |
| **RF12** | Registrar trajetória do produtor | **HU12** — Como produtor ou responsável, quero cadastrar uma experiência, para divulgar turismo, vivências e outras atividades. | **CA01:** O responsável deve conseguir cadastrar uma experiência.<br>**CA02:** O sistema deve exigir as informações obrigatórias da experiência.<br>**CA03:** Após o cadastro, a experiência deve ficar disponível para consulta conforme suas condições de publicação. |
| **RF14** | Consultar perfil de produtor | **HU14** — Como consumidor ou visitante, quero buscar produtos e experiências, para encontrar ofertas com mais rapidez. | **CA01:** O sistema deve disponibilizar um campo de busca.<br>**CA02:** A busca deve retornar resultados relacionados ao termo informado.<br>**CA03:** Quando não houver correspondências, o sistema deve informar que nenhum resultado foi encontrado. |
| **RF17** | Cadastrar produto | **HU17** — Como consumidor ou visitante, quero consultar o status da minha pré-reserva, para acompanhar se foi recebida, respondida ou alterada. | **CA01:** O usuário deve conseguir consultar suas solicitações de pré-reserva.<br>**CA02:** Cada solicitação deve apresentar seu status atual.<br>**CA03:** O status deve ser atualizado quando houver uma nova resposta ou alteração. |
| **RF21** | Consultar catálogo de produtos | **HU21** — Como administrador, quero desativar a conta de um usuário quando necessário, para impedir seu acesso em casos administrativos ou de descumprimento das regras da plataforma. | **CA01:** O administrador deve conseguir selecionar um usuário cadastrado.<br>**CA02:** O sistema deve solicitar confirmação antes da desativação.<br>**CA03:** Após a desativação, o usuário não deve conseguir acessar as funcionalidades destinadas a contas ativas. |
| **RF22** | Consultar detalhes do produto | **HU22** — Como administrador, quero consultar os produtos, experiências e eventos cadastrados, para acompanhar os conteúdos publicados pelos produtores. | **CA01:** O administrador deve conseguir consultar os conteúdos cadastrados.<br>**CA02:** A consulta deve permitir identificar o responsável por cada conteúdo.<br>**CA03:** O sistema deve diferenciar os tipos de conteúdo apresentados. |
| **RF23** | Cadastrar experiência | **HU23** — Como administrador, quero remover conteúdos que violem as regras da plataforma, para manter as ofertas e informações adequadas aos usuários. | **CA01:** O administrador deve conseguir selecionar um conteúdo para remoção.<br>**CA02:** O sistema deve solicitar confirmação da ação.<br>**CA03:** Após a remoção, o conteúdo não deve permanecer disponível para consulta pública. |
| **RF25** | Consultar experiência | **HU25** — Como usuário cadastrado, quero excluir minha própria conta, para deixar de utilizar a plataforma quando desejar. | **CA01:** O usuário autenticado deve conseguir iniciar a exclusão da própria conta.<br>**CA02:** O sistema deve solicitar confirmação antes da exclusão.<br>**CA03:** Após a exclusão, o usuário não deve conseguir utilizar a conta removida para autenticação. |
| **RF36** | Buscar ofertas | **HU36** — Como consumidor ou visitante, quero consultar os eventos cadastrados, para conhecer sua descrição, local e período de realização. | **CA01:** O sistema deve apresentar os eventos disponíveis para consulta.<br>**CA02:** Cada evento deve apresentar descrição, local e período quando essas informações estiverem cadastradas.<br>**CA03:** O usuário deve conseguir acessar os detalhes de um evento. |
| **RF39** | Disponibilizar contato direto | **HU39** — Como consumidor ou visitante, quero conhecer a história e os principais pontos de interesse da Cafuringa, para compreender melhor a região. | **CA01:** O sistema deve disponibilizar informações sobre a história da Cafuringa.<br>**CA02:** O sistema deve apresentar os principais pontos de interesse cadastrados.<br>**CA03:** As informações devem estar disponíveis para consulta de visitantes e consumidores. |
| **RF44** | Solicitar pré-reserva de experiência | **HU44** — Como consumidor ou visitante, quero filtrar os resultados da busca por produto, experiência, atividade, perfil ou outra categoria disponível, para encontrar ofertas relevantes. | **CA01:** O sistema deve disponibilizar filtros compatíveis com as categorias cadastradas.<br>**CA02:** A aplicação de um filtro deve atualizar os resultados apresentados.<br>**CA03:** O usuário deve conseguir remover os filtros aplicados. |
| **RF45** | Consultar pré-reserva | **HU45** — Como consumidor ou visitante, quero enviar feedback diretamente ao fornecedor sobre uma oferta ou experiência, para compartilhar minha opinião com o responsável. | **CA01:** O usuário deve conseguir iniciar o envio de feedback para uma oferta ou experiência.<br>**CA02:** O sistema deve permitir informar o conteúdo do feedback.<br>**CA03:** Após o envio válido, o feedback deve ser registrado e associado à oferta correspondente. |
| **RF46** | Cancelar solicitação de pré-reserva | **HU46** — Como usuário ou produtor envolvido, quero visualizar feedback de produtos, experiências ou eventos relacionados a mim, para acompanhar os comentários registrados. | **CA01:** O usuário autorizado deve conseguir consultar os feedbacks relacionados às ofertas correspondentes.<br>**CA02:** Cada feedback deve apresentar seu conteúdo e contexto de origem.<br>**CA03:** Feedbacks inexistentes devem resultar em uma indicação de que não há registros disponíveis. |
| **RF47** | Responder pré-reserva de experiência | **HU47** — Como usuário, quero editar um feedback que enviei, para corrigir ou atualizar as informações da minha manifestação. | **CA01:** O usuário deve conseguir selecionar um feedback próprio para edição.<br>**CA02:** O sistema deve permitir alterar o conteúdo do feedback.<br>**CA03:** Após o salvamento, o feedback deve apresentar a versão atualizada. |
| **RF48** | Notificar alteração de pré-reserva | **HU48** — Como usuário, quero excluir um feedback que enviei ao fornecedor, para retirar uma manifestação que não desejo mais manter. | **CA01:** O usuário deve conseguir selecionar um feedback próprio para exclusão.<br>**CA02:** O sistema deve solicitar confirmação antes da exclusão.<br>**CA03:** Após a confirmação, o feedback deve deixar de ser apresentado como registro ativo. |

## Critérios de Aceitação (Todos Requisitos)

A tabela a seguir apresenta o conjunto completo de requisitos funcionais da Rede Cafuringa, incluindo tanto os requisitos contemplados no MVP quanto aqueles previstos para etapas posteriores do desenvolvimento. Cada requisito está relacionado a uma História de Usuário específica, mantendo a correspondência de um para um entre RF e HU. Para cada história de usuário são definidos um ou mais Critérios de Aceitação, utilizados como condições verificáveis para determinar se a funcionalidade atende ao comportamento esperado. A tabela permite, portanto, visualizar a relação entre o que o sistema deve oferecer, a necessidade do usuário que origina cada funcionalidade e as condições utilizadas para sua validação.
