# HU10 — Recuperar acesso à conta (backend)

> História: [HU10](../../../visao/historias/HU10.md) · RF10 · RN05 · RNF03, RNF08, RNF10, RNF11 · Decisão técnica [D11](../poc.md).
> Operação (variáveis, SMTP, índices): [operação, 3.2](../operacao.md). Controles e riscos: [segurança](../seguranca.md).

## 1. O que foi entregue

O usuário cadastrado (consumidor, produtor ou administrador) informa o e-mail da
conta, recebe nele um link de uso único e define uma nova senha. A API não revela
se o e-mail está cadastrado.

| Método e rota | Acesso | Função | Respostas |
|---|---|---|---|
| `POST /api/v1/auth/password-reset/request` | público, limite estrito | Pede a recuperação (CA02/CA03) | **202** sempre igual · 400 e-mail inválido · 429 |
| `POST /api/v1/auth/password-reset/validate` | público, limite estrito | Diz se o link ainda vale (CA04); não consome | **200** `{ "valido": true }` · 400 link inválido/expirado/usado · 429 |
| `POST /api/v1/auth/password-reset/confirm` | público, limite estrito | Troca a senha e consome o link (CA05/CA06) | **200** · 400 senha fora da política ou link inválido · 429 |

Contrato completo (campos, exemplos, erros): [Referência da API](../../shared/api.md), tag `auth`. Versão do contrato: **0.4.0**.

## 2. Fluxo

```mermaid
sequenceDiagram
    participant F as Front (PWA)
    participant A as API
    participant D as MongoDB
    participant M as SMTP
    F->>A: POST /request { email }
    A-->>F: 202 mensagem genérica, na hora (igual em todos os casos)
    Note over A: daqui em diante, fora do caminho da resposta
    A->>D: busca conta ativa pelo e-mail
    alt conta ativa
        A->>D: upsert do pedido da conta (índice único em userId), só se fora do intervalo mínimo
        A->>M: envia <APP_PUBLIC_URL>/#/nova-senha?token=... (reenvia após falha)
        opt e-mail não entregue após os reenvios
            A->>D: desfaz o pedido e incrementa a métrica de falha
        end
    end
    F->>A: POST /validate { token }
    A-->>F: 200 { valido: true } ou 400
    F->>A: POST /confirm { token, novaSenha }
    A->>D: consome o token de forma atômica (usedAt)
    A->>D: grava o hash argon2id da nova senha e credenciaisAlteradasEm; apaga o pedido
    A-->>F: 200 "Recuperação de acesso concluída..."
    Note over A: JWTs emitidos antes da troca passam a receber 401
```

## 4. Dados

Coleção `password_reset_tokens` (no máximo um pedido pendente por conta):

| Campo | Tipo | Observação |
|---|---|---|
| `userId` | ObjectId | Conta dona do pedido (**índice único**: um pedido por conta, sem corrida entre pedidos simultâneos) |
| `tokenHash` | string | SHA-256 do token (índice único). O token em si nunca é gravado |
| `expiresAt` | Date | Índice TTL: o Mongo apaga o documento quando vence |
| `usedAt` | Date? | Preenchido no consumo; garante o uso único |
| `createdAt` | Date | Gravado pelo service; base do intervalo mínimo entre pedidos |

Na coleção `users`, a redefinição troca `senhaHash` e grava `credenciaisAlteradasEm`
(novo campo opcional), que o `JwtAuthGuard` compara com o `iat` dos tokens.
Os índices de `password_reset_tokens` são garantidos pela própria API na subida
(idempotente); o `./scripts/dev.sh indexes --prod` continua sendo o passo de deploy
para os demais índices.

## 5. Como o front conecta

1. **Tela "Esqueci minha senha"** (link na tela de login, CA01): `POST /auth/password-reset/request` com `{ email }`. Em **202**, mostre `mensagem` da resposta, sem afirmar que a conta existe. Em **400**, mostre `message` (lista) junto ao campo. Em **429**, respeite o cabeçalho `Retry-After` (segundos) antes de habilitar "Reenviar".
2. **Rota `#/nova-senha?token=...`** (destino do link do e-mail, no formato da rota por hash do app): **a rota `/nova-senha` precisa estar na lista de `app/src/app/useHashRoute.ts`** (já está; sem isso o app redireciona para `/escolher-perfil`). O token está dentro do fragmento: leia-o da query do hash (`new URLSearchParams(location.hash.split('?')[1]).get('token')`) e **remova-o da barra de endereço** em seguida (`history.replaceState(null, '', '#/nova-senha')`), para ele não ficar no histórico. Chame `POST /auth/password-reset/validate`. Em **200**, mostre o formulário de nova senha; em **400**, mostre `message` e um botão para pedir novo link.
3. **Enviar a nova senha:** `POST /auth/password-reset/confirm` com `{ token, novaSenha }`. Política: 8 a 128 caracteres, com letra e número (mesma do cadastro). Em **400** por senha fraca, o link continua válido: mantenha o formulário preenchido (RNF03). Em **200**, mostre `mensagem` e leve ao login.
4. Não envie `Authorization` nessas rotas e não guarde o token em `localStorage` nem no cache do service worker.
5. **Depois da troca**, sessões abertas em outros aparelhos recebem **401** com `Sessão encerrada. Faça login novamente.`: trate como logout e leve ao login.

Tipos prontos em `app/src/shared/api/schema.ts` (`RequestPasswordResetDto`, `ValidateResetTokenDto`, `ConfirmPasswordResetDto` e as respostas).

## 6. Decisões

| Decisão | Motivo | Alternativa descartada |
|---|---|---|
| Link com token (D11) em vez de código numérico | Já previsto no POC e no protótipo; 256 bits dispensam bloqueio por tentativas | Código de 6 dígitos: exigiria contador de tentativas por conta |
| `MailService` + nodemailer/SMTP gratuito | Custo zero (RNF13); o transporte `log` permite desenvolver sem SMTP | Provedor com SDK pago |
| Resposta 202 antes de qualquer trabalho; processamento depois | Tempo de resposta igual exista ou não a conta (sem oráculo de tempo) | Equalizar com trabalho falso: frágil e mais caro |
| Reenvio em memória com espera crescente + métrica, sem outbox | Cobre quedas passageiras do SMTP com custo zero; o outbox (D6) chega com as notificações (RF48) | Outbox já agora: aumentaria o escopo da HU |
| E-mail perdido desfaz o pedido | A pessoa pode pedir de novo na hora, sem esperar o intervalo por um link que não chegou | Manter o pedido e obrigar a esperar 60 s |
| Um pedido por conta com índice único + upsert condicionado | Atômico no próprio Mongo: pedidos simultâneos geram um único link e um único e-mail | Ler e depois gravar (corrida) |
| Token no fragmento do link (`/#/nova-senha?token=`), no formato da rota por hash do app | O navegador não envia o fragmento ao servidor nem no `Referer`: o token não vai a logs do front, CDN ou terceiros. O formato segue o roteamento existente do front (`useHashRoute`) | `/nova-senha?token=` fora do hash (iria ao servidor); `/nova-senha#token=` (incompatível com o roteamento do app) |
| Validação e confirmação por `POST`, token no corpo | O token não aparece em logs de acesso da API nem em proxies | `GET ?token=` |
| Revogação pelo `JwtAuthGuard` com `credenciaisAlteradasEm` | Trocar a senha encerra sessões roubadas na hora; também fecha o caso de conta desativada com token válido. Custo: uma leitura por `_id` por requisição autenticada | Lista de tokens revogados; refresh token (fora do escopo) |
| Mesma mensagem para token inexistente, usado, expirado ou de conta desativada | Não dá pistas a quem tenta adivinhar tokens | Mensagens distintas |

## 7. Fora do escopo e pendências

- Melhorias do front sobre o passo 2 acima, ainda não feitas: chamar `POST /auth/password-reset/validate` ao abrir o link (hoje um link inválido só é descoberto ao enviar a nova senha, quando o `confirm` devolve 400 com a orientação) e remover o token da barra de endereço com `history.replaceState` depois de lido.
- Fila persistente de e-mail (outbox, D6): o reenvio atual se perde se a API reiniciar durante as tentativas (ver [segurança, item 9](../seguranca.md)).
- Configurar SPF/DKIM do domínio remetente no provedor SMTP e a regra de alerta de `cafuringa_mail_delivery_failures_total` antes de produção.
